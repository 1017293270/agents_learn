# 大模型基础概念

## 我学到的核心点

大模型不是“会聊天的软件”，而是一类用大量数据训练出来、能根据输入上下文生成或理解内容的模型。对初学者来说，先把 5 件事分清楚：

1. 模型输入输出的基本单位通常是 token。
2. 语言模型生成文本时，本质上是在预测后续 token。
3. Transformer 是现代大语言模型的关键基础架构之一。
4. “模型类型”要按能力、模态、部署方式、训练阶段分维度看。
5. 模型强不强，不只看参数大小，还要看数据、训练方法、推理策略、工具能力和使用场景。

## 它是什么

大模型通常指参数规模大、训练数据量大、具备较强泛化能力的机器学习模型。这里重点讨论大语言模型 LLM，以及和 LLM 关系很近的多模态模型、embedding 模型、推理模型。

一个最简单的理解：

```text
用户输入 -> 切成 token -> 模型根据上下文计算概率 -> 逐步生成输出 token -> 还原成人能读的文本
```

模型不是数据库。它不会像查表一样“保证拿到事实”。它更像一个强大的模式生成器：根据上下文、训练中学到的语言和知识模式，生成最可能有用的回答。

## 它不是什么

- 不是搜索引擎：除非接入搜索或检索，否则它不一定知道最新信息。
- 不是知识库：它可能记得训练中见过的模式，但不能保证准确引用来源。
- 不是程序员本人：它能写代码，但仍需要测试和审查。
- 不是自动安全系统：它可能被误导、被注入、被诱导越权。
- 不是越大越适合所有任务：小模型在固定任务、低延迟、低成本场景可能更合适。

## 基础术语

| 术语 | 通俗解释 | 为什么重要 |
| --- | --- | --- |
| Token | 模型处理文本的基本片段，可能是字、词或词的一部分 | 费用、上下文长度、生成速度都和 token 有关 |
| 参数 | 模型内部可学习的数字权重 | 参数多通常容量更大，但不是唯一指标 |
| 上下文窗口 | 模型一次能看到的 token 范围 | 决定能放多少历史、资料和指令 |
| Prompt | 你给模型的输入和指令 | 决定模型如何理解任务 |
| Completion / Response | 模型生成的输出 | 需要检查格式、事实和安全性 |
| Pretraining | 预训练，让模型学习语言和世界知识模式 | 是通用能力来源 |
| SFT | 监督微调，用高质量示例教模型按期望回答 | 常用于风格、格式、任务行为 |
| RLHF | 人类反馈强化学习，用偏好反馈让模型更符合人类期望 | 常用于对齐、安全和指令跟随 |
| Inference | 推理，模型已经训练好后实际生成输出 | 影响成本、延迟和用户体验 |

## 大模型的主要分类

### 按模态分类

| 类型 | 输入 | 输出 | 例子 |
| --- | --- | --- | --- |
| 语言模型 | 文本 | 文本 | 问答、总结、写作、代码 |
| 多模态模型 | 文本、图片、音频、视频、PDF 等 | 文本或多模态内容 | 看图问答、视频理解、文档分析 |
| 图像生成模型 | 文本、图片 | 图片 | 海报、产品图、概念设计 |
| 语音模型 | 音频或文本 | 文本或音频 | 语音识别、语音合成、实时对话 |
| Embedding 模型 | 文本、图片等 | 向量 | 搜索、推荐、聚类、RAG |

### 按使用方式分类

| 类型 | 适合做什么 | 初学者判断方式 |
| --- | --- | --- |
| Chat / 通用模型 | 对话、写作、总结、问答 | 默认从这里开始 |
| Reasoning model | 数学、代码、复杂推理、规划 | 问题需要多步推理时考虑 |
| Embedding model | 相似度搜索、RAG 检索 | 不直接回答用户，而是把内容变成向量 |
| Reranker | 给候选结果重新排序 | 检索质量不稳定时考虑 |
| Code model | 写代码、改代码、查 bug | 编程任务优先考虑 |
| Tool-use model | 决定何时调用工具 | Agent 和自动化任务需要 |

### 按开放方式分类

| 类型 | 优点 | 风险 |
| --- | --- | --- |
| 闭源 API 模型 | 上手快、能力强、维护少 | 成本、数据合规、供应商锁定 |
| 开源或开放权重模型 | 可本地部署、可控性强 | 部署成本高，需要工程能力 |
| 本地小模型 | 延迟低、隐私强、成本可控 | 能力有限，维护和评估仍要做 |
| 微调模型 | 更贴合特定任务 | 数据质量差会把模型带偏 |

## Transformer 为什么重要

Transformer 的核心贡献是用 attention 机制处理序列关系，让模型能更高效地学习上下文里不同位置之间的关系。

初学者不需要一开始就推公式，但要理解三点：

1. 模型不是逐字死记硬背，而是在上下文中计算“哪些信息更相关”。
2. Attention 让模型能在长文本里关注重要 token。
3. 现代 LLM 虽然做了很多改造，但 Transformer 仍是非常重要的基础。

一个类比：你读一篇文章回答问题时，不会平均看每个字，而会回头关注和问题最相关的句子。Attention 做的是类似的“相关性分配”，只是它用矩阵计算完成。

## 大模型从训练到使用的链路

```text
大规模数据
  -> 预训练
  -> 基础模型
  -> SFT / 指令微调
  -> 偏好对齐，如 RLHF
  -> 安全评估
  -> API 或本地部署
  -> Prompt / RAG / Tool calling / Agent 应用
```

不要把这些阶段混在一起：

- 预训练解决通用能力。
- SFT 教模型“按示例做事”。
- RLHF/RFT 等对齐方法让模型更符合偏好或评分标准。
- Prompt 是使用阶段的任务表达。
- RAG 是使用阶段补充外部资料。
- Tool calling 是使用阶段连接外部动作。

## 常见误区

### 误区 1：参数越大越好

参数大通常意味着容量强，但最终效果还受训练数据、架构、推理策略、微调、工具和任务匹配影响。一个小模型在固定分类任务上可能比大模型更划算。

### 误区 2：模型回答流畅就等于正确

流畅只说明语言模式自然，不说明事实可靠。重要知识必须查来源或做实验。

### 误区 3：上下文越长越安全

长上下文能放更多资料，但也可能让模型被无关信息干扰。长上下文不等于理解更深。

### 误区 4：Prompt 可以解决所有问题

Prompt 能改善指令表达，但事实缺失要靠检索，外部动作要靠工具，稳定格式要靠结构化输出，安全要靠权限和审计。

### 误区 5：开源模型就一定更便宜

开源权重不等于零成本。显卡、运维、推理服务、监控、人员时间都要算。

## 初学者学习路线

1. 先理解 token、上下文窗口、生成、温度、幻觉。
2. 学会写清楚 prompt。
3. 理解 RAG、embedding 和检索。
4. 理解 tool calling，让模型连接外部能力。
5. 理解推理部署的成本和延迟。
6. 再学习 SFT、RLHF、RFT 等训练和对齐方法。
7. 最后做模型对比和选型。

## 实践判断

- 如果只是想完成日常问答和写作，先学 Prompt 工程。
- 如果模型缺资料，学 RAG 和检索。
- 如果模型需要执行动作，学 tool calling 和权限控制。
- 如果模型风格或格式长期不稳定，再考虑 SFT。
- 如果任务需要专家评分和复杂推理优化，再研究 RFT/RLHF 类方法。
