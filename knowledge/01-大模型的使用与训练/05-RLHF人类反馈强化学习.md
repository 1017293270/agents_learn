# RLHF 人类反馈强化学习

## 我学到的核心点

RLHF 是 `Reinforcement Learning from Human Feedback` 的缩写，中文常译为“基于人类反馈的强化学习”或“人类反馈强化学习”。

理解这个英文全称很重要，因为它直接说明了 RLHF 的结构：

- `Reinforcement Learning`：强化学习，一类通过反馈信号不断调整行为的机器学习方法。
- `from Human Feedback`：反馈不是普通环境自动给出的，而是来自人类对模型输出的偏好、评价或比较。

所以 RLHF 的核心不是“人类直接写标准答案”，而是“人类告诉系统哪些回答更好，模型再通过这种反馈逐步学会更符合人类偏好的回答”。

## 先拆开英文缩写

| 缩写部分 | 英文 | 中文 | 在 RLHF 里的含义 |
| --- | --- | --- | --- |
| RL | Reinforcement Learning | 强化学习 | 通过奖励或惩罚信号调整行为 |
| H | Human | 人类 | 反馈来自人类判断，而不是纯自动规则 |
| F | Feedback | 反馈 | 人类对多个回答进行比较、排序或评价 |

初学者可以先记住一句话：

```text
RLHF = 用人类反馈作为奖励信号，训练模型更偏向产生人类认为更好的回答。
```

## 强化学习是什么

强化学习是机器学习的一种。它和“给一堆标准答案让模型模仿”的监督学习不一样，更像是“让系统在环境里尝试行动，然后根据反馈逐步变好”。

一个经典例子是机器人学习走路：

```text
机器人做一个动作
  -> 环境发生变化
  -> 系统得到反馈：走稳了加分，摔倒了扣分
  -> 机器人调整策略
  -> 反复尝试，逐步学会更好的动作
```

强化学习里常见的几个词：

| 术语 | 通俗解释 | 机器人例子 | RLHF 里的对应关系 |
| --- | --- | --- | --- |
| Agent | 做决策的主体 | 机器人 | 语言模型 |
| Environment | 行动所在的环境 | 房间、地面、障碍物 | 用户问题、对话上下文、任务场景 |
| Action | agent 做出的动作 | 抬腿、转向 | 生成一段回答 |
| Reward | 反馈分数 | 走稳加分，摔倒扣分 | 人类偏好或奖励模型分数 |
| Policy | 行动策略 | 什么时候迈哪条腿 | 模型在某种输入下倾向生成什么回答 |

强化学习通常用在游戏、机器人控制、推荐策略、资源调度等场景，因为这些任务不一定每一步都有标准答案，但可以通过结果反馈判断行为好坏。

把这个思想搬到大模型上，就得到一个直觉：模型生成回答就像 agent 做动作，人类反馈就像环境给奖励。模型不是只模仿一个标准答案，而是根据“哪些回答更受人类偏好”来调整自己的输出倾向。

## 为什么需要 RLHF

预训练语言模型主要学会“预测文本”。但用户真正想要的是：

- 听懂指令。
- 不胡乱编造。
- 回答有帮助。
- 避免危险内容。
- 风格自然且可控。

预训练目标和用户目标并不完全一致，所以需要对齐。RLHF 就是对齐方法之一。

## RLHF 的典型流程

InstructGPT 论文中的典型流程可以简化成三步：

```text
1. SFT：用人工示范答案训练一个初始指令模型
2. Reward Model：让人工比较多个模型答案，训练奖励模型
3. RL：用奖励模型打分，强化模型生成更高偏好分的答案
```

### 第 1 步：人工示范

标注者写出高质量答案，模型先学会基本指令跟随。

### 第 2 步：偏好比较

对同一个 prompt，模型生成多个答案。标注者比较哪个更好。比如：

```text
回答 A：准确但太短
回答 B：详细但编造了事实
回答 C：准确、清楚、没有编造
```

标注者可能选择 C。大量这样的偏好数据可以训练奖励模型。

### 第 3 步：强化学习优化

模型生成答案，奖励模型给分，训练算法让高分答案更可能出现。

## RLHF 和 SFT 的区别

| 维度 | SFT | RLHF |
| --- | --- | --- |
| 数据形式 | 输入 + 理想输出 | 输入 + 多个输出的偏好比较 |
| 目标 | 模仿示例 | 优化偏好 |
| 适合 | 固定格式、风格、任务行为 | 有多种可接受答案但质量有高低 |
| 难点 | 高质量示例 | 偏好一致性、奖励模型偏差 |
| 成本 | 相对低 | 通常更高 |

## RLHF 适合解决什么

- 让模型更会听指令。
- 让模型回答更符合人类偏好。
- 减少明显不安全或不合适回答。
- 在多个答案都“差不多对”时，学会更好的表达和取舍。

## RLHF 不能解决什么

- 不能保证事实永远正确。
- 不能让模型凭空学会训练数据里没有的专业能力。
- 不能替代检索、工具、权限和审计。
- 不能保证所有人的偏好一致。
- 不能完全消除偏见和安全风险。

## 奖励模型的风险

奖励模型本身也是模型，也会出错。常见风险：

- 偏好数据偏差：标注者群体不代表真实用户。
- 奖励黑客：模型学会讨好奖励模型，而不是真正做好任务。
- 过度拒答：为了安全，模型可能变得不愿回答正常问题。
- 风格趋同：模型变得礼貌但空泛。
- 长答案偏好：标注者可能更容易偏好看起来更详细的答案。

## RFT 和 RLHF 的关系

OpenAI 的 Reinforcement Fine-Tuning 文档描述了一类更产品化的强化微调：用户提供可编程 grader，让模型根据评分信号优化。它和传统 RLHF 的共同点是“用反馈信号优化模型行为”，不同点是反馈不一定来自人工偏好比较，也可以来自可执行评分器。

初学者可以这样理解：

- RLHF：人类比较答案，训练偏好。
- RFT：用你定义的评分器给答案打分，优化特定任务。

二者都比普通 prompt 更重，适合更稳定、更高价值、更专业的任务。

## 初学者例子

任务：让模型回答法律条文问题。

SFT 数据可以告诉模型：

```text
输入：某个法律问题
输出：结构化回答，包括结论、依据、风险提示
```

RLHF/RFT 可以进一步优化：

- 回答是否引用了正确条文。
- 是否遗漏关键限制。
- 是否把不确定内容说得太绝对。
- 是否给出不该给的法律结论。

但真实法律产品仍然需要专业审核，不能只靠 RLHF。

## 常见误区

### 误区 1：RLHF 后模型就安全了

RLHF 只能降低风险，不能消除风险。系统仍需要安全策略、权限、日志和人工审核。

### 误区 2：偏好就是事实

人类偏好可以选择“更好回答”，但事实正确性仍需要来源、检索和验证。

### 误区 3：RLHF 比 SFT 永远更高级

不是。很多业务任务用 SFT 或 prompt + eval 就足够。RLHF 成本高，复杂度高。

### 误区 4：标注者越多越好

数量重要，但标注标准、一致性和专业性更重要。

## 实践判断

- 如果你没有稳定 eval，不要急着做 RLHF/RFT。
- 如果任务有明确正确答案，先用 SFT 或监督数据。
- 如果任务答案开放但质量差异明显，再考虑偏好反馈。
- 如果能写出可靠 grader，可以研究 RFT。
- 如果涉及医疗、法律、金融等高风险领域，必须保留专家审查。
