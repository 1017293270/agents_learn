# 常用大模型对比

## 我学到的核心点

模型对比不要做成“谁最强”的永久排行榜，而要做成“任务选型表”。同一个模型，在写代码、长文档分析、低成本批处理、实时语音、多模态理解、私有化部署这些场景里的价值完全不同。

本小节基于 2026-06-08 访问到的官方资料整理，具体模型名、价格、上下文窗口和能力可能很快变化。

## 先看选择维度

| 维度 | 问题 |
| --- | --- |
| 任务类型 | 写作、代码、推理、客服、搜索、图像、语音、工具调用？ |
| 输入模态 | 只有文本，还是图片、音频、视频、PDF？ |
| 输出形式 | 文本、JSON、代码、语音、图片？ |
| 质量要求 | 可接受大概正确，还是必须高可靠？ |
| 延迟要求 | 可以等 30 秒，还是要实时？ |
| 成本 | 少量高质量，还是海量低成本？ |
| 上下文 | 是否要读长文档、代码库、会议记录？ |
| 工具能力 | 是否需要函数调用、搜索、代码执行？ |
| 部署 | API、私有化、本地、边缘设备？ |
| 合规 | 数据能不能出内网？日志如何处理？ |

## 常见模型家族

### OpenAI

官方模型文档把模型按 frontier、mini/nano、Codex、image、audio、realtime、embedding、moderation、open-weight 等类别组织。

适合关注：

- 通用高能力任务。
- 代码和 agentic coding。
- 工具调用和结构化输出生态。
- 图像、音频、实时、多模态 API。
- embedding 和 moderation 等配套能力。

风险：

- 具体模型版本和名称变化快。
- 成本和能力要以官方模型页为准。
- API 平台能力强，但私有化部署选择有限。

### Anthropic Claude

Claude 官方模型文档按 Opus、Sonnet、Haiku 等定位比较模型，并强调推理、编码、长上下文、视觉和多语言能力。官方文档还给出模型 ID、上下文、输出上限、知识截止和平台可用性。

适合关注：

- 长文本阅读和分析。
- 复杂推理和编码。
- 企业知识工作和高自治任务。

风险：

- 不同平台上的上下文和功能可能不同。
- 模型 ID 和 alias 需要区分 pinned snapshot 与便利指针。
- 价格、上下文和输出上限变化快。

### Google Gemini

Gemini 官方文档按 Pro、Flash、Flash-Lite 等定位模型，并列出多模态输入、函数调用、结构化输出、搜索 grounding、URL context、thinking 等能力。

适合关注：

- 多模态输入，如文本、图片、视频、音频、PDF。
- 超长上下文。
- Google 生态和 AI Studio / Vertex AI。
- 低延迟与高吞吐任务中的 Flash 系列。

风险：

- Preview、latest、stable 版本要区分。
- 不同国家、平台和版本可用能力可能不同。

### Mistral

Mistral 官方文档和模型页强调开放模型、代码模型、文档 AI、语音/OCR 等产品线。

适合关注：

- 开放模型和可部署模型。
- 欧洲生态和企业部署。
- 代码、OCR、语音等垂直能力。

风险：

- 不同模型许可、部署方式、平台可用性需要逐个查。
- 开放模型也需要推理部署和运维能力。

### 开源 / 开放权重模型

这里包括 Llama、Qwen、DeepSeek、Mistral open models、gpt-oss 等生态。优点是可控、可本地部署、可微调；缺点是需要工程能力。

适合关注：

- 数据不能出内网。
- 需要低成本批量推理。
- 需要控制模型权重、量化、微调和部署。

风险：

- 不是下载就能生产可用。
- 需要处理推理服务、显存、量化、评估、安全和更新。

## 选型建议

### 初学者做个人学习

优先选：

- 一个强 API 模型，用来学习 prompt、RAG、tool calling。
- 一个本地小模型，用来理解部署和推理成本。

不要一开始纠结所有模型排名。

### 做产品原型

优先选：

- API 模型。
- 支持结构化输出、工具调用、流式输出和稳定版本。
- 配合 eval 记录质量。

### 做企业知识库

关注：

- 长上下文。
- RAG 能力。
- 数据合规。
- 引用来源。
- 权限过滤。
- 成本和延迟。

### 做代码 agent

关注：

- 代码能力。
- 长上下文。
- 工具调用。
- 文件编辑能力。
- 测试和命令执行安全。

### 做私有化部署

关注：

- 模型权重许可。
- 显存需求。
- 量化后质量。
- vLLM/TGI/SGLang/llama.cpp 等推理引擎。
- 监控和扩容。

## 模型对比表

| 家族 | 常见定位 | 适合任务 | 主要风险 |
| --- | --- | --- | --- |
| OpenAI GPT 系列 | 通用、代码、工具、多模态、音频、embedding 生态完整 | 原型、产品 API、agent、结构化输出 | 平台依赖，模型变化快 |
| Claude | 长文档、推理、编码、知识工作 | 文档分析、企业知识、复杂代码任务 | 平台差异和版本差异 |
| Gemini | 多模态、长上下文、Google 生态 | 视频/音频/PDF 分析、搜索 grounding | preview/stable 区分复杂 |
| Mistral | 开放模型、企业部署、代码/OCR/语音产品线 | 私有化、欧洲企业生态、开放模型实验 | 需逐个确认模型许可和部署 |
| 开放权重模型 | 可控、本地、可微调 | 内网部署、低成本批处理、研究实验 | 运维和评估成本高 |

## 初学者不要这样比

- 不要只看排行榜。
- 不要只看参数量。
- 不要只看上下文长度。
- 不要只看单次回答体验。
- 不要把 ChatGPT、Claude、Gemini app 的体验直接等同于 API 模型能力。

更好的方法是：准备自己的 20 个真实任务，固定评价标准，比较输出质量、成本、延迟和失败模式。

## 来源与证据

- 来源：OpenAI Models；Claude models overview；Gemini models；Mistral AI docs；`90-references/llm-use-training-references.md`。
- 证据摘要：各官方文档都按不同模型定位、能力、上下文、模态和平台可用性说明模型；本笔记基于这些资料总结选型维度。
- 可信度判断：模型家族定位来自官方资料，可信度中高；具体“哪个最好”不稳定，所以本卡不写永久排名。
