# 前向传播与损失函数

## 一句话结论

前向传播负责把输入算成预测，损失函数负责把预测和真实目标之间的差距变成一个可优化的数；没有合适的损失函数，模型不知道什么叫“变好”。

## 概念定位

- 它是什么：训练中从输入到预测再到损失值的计算过程。
- 它不是什么：不是参数更新本身，参数更新发生在反向传播和优化器步骤之后。
- 相邻概念：logits、activation、softmax、cross entropy、MSE、objective function。
- 前置知识：神经网络基础、特征表示、标签、概率。

初学者可以先记住：

```text
前向传播回答：模型现在预测什么？
损失函数回答：这个预测错得有多严重？
```

## 缩写全称速查

| 缩写 | 英文全称 | 中文解释 | 初学者理解 |
| --- | --- | --- | --- |
| MSE | Mean Squared Error | 均方误差 | 回归任务常用，预测和真实值差距平方后取平均 |
| MAE | Mean Absolute Error | 平均绝对误差 | 对误差取绝对值再平均 |
| BCE | Binary Cross Entropy | 二元交叉熵 | 二分类任务常用损失 |
| CE | Cross Entropy | 交叉熵 | 多分类任务常用损失 |
| NLL | Negative Log Likelihood | 负对数似然 | 让正确答案的概率越高越好 |
| KL | Kullback-Leibler Divergence | KL 散度 | 衡量两个概率分布差异 |
| RMSE | Root Mean Squared Error | 均方根误差 | MSE 开平方，单位和目标一致 |
| MAPE | Mean Absolute Percentage Error | 平均绝对百分比误差 | 用百分比衡量预测误差 |
| BCEWithLogitsLoss | Binary Cross Entropy With Logits Loss | 带 logits 的二元交叉熵 | 把 sigmoid 和 BCE 合在一起，数值上更稳定 |

Logits 不是缩写，指模型在 softmax 或 sigmoid 之前输出的原始分数。

## 核心概念

### 1. 前向传播

Forward pass 指输入经过模型层层计算得到输出。

```text
features -> model -> logits -> probabilities -> prediction
```

例如二分类：

```text
用户特征 -> 神经网络 -> logit -> sigmoid -> 点击概率
```

### 2. Logits

Logits 是模型直接输出的分数，通常还不是概率。

```text
logits = [2.1, -0.3, 0.8]
```

经过 softmax 才会变成多分类概率。

### 3. Activation

Activation function 指激活函数。常见：

| 激活函数 | 作用 | 常见位置 |
| --- | --- | --- |
| ReLU | 引入非线性，计算简单 | 隐藏层 |
| Sigmoid | 输出 0 到 1 | 二分类概率 |
| Softmax | 多类别概率归一化 | 多分类输出层 |
| GELU | 平滑非线性 | Transformer 常见 |

### 4. Loss 和 objective

Loss 是单个样本或 batch 的错误度量。Objective 是训练整体要优化的目标，可能包括：

```text
objective = loss + regularization
```

例如：

```text
总目标 = 分类交叉熵 + 权重衰减项
```

### 5. PyTorch 中 logits 和 loss 的常见约定

在 PyTorch 里，很多分类损失函数希望你传入 raw logits，而不是已经 softmax 或 sigmoid 后的概率。

常见入门规则：

| 任务 | 推荐输出 | 常用 loss | 注意 |
| --- | --- | --- | --- |
| 多分类 | `[B, C]` logits | `CrossEntropyLoss` | 通常不要先手动 softmax |
| 二分类 | `[B, 1]` logits | `BCEWithLogitsLoss` | 通常不要先手动 sigmoid |
| 多标签 | `[B, num_labels]` logits | `BCEWithLogitsLoss` | 每个标签独立判断 |

如果先 sigmoid 再用 `BCEWithLogitsLoss`，或先 softmax 再用 `CrossEntropyLoss`，就容易重复计算激活，导致训练含义或数值稳定性出问题。

## 机制与原理

以三分类为例：

```text
输入 x
  -> 模型
  -> logits = [2.0, 0.5, -1.0]
  -> softmax
  -> probabilities = [0.79, 0.18, 0.03]
```

如果真实类别是第 1 类，那么损失较小；如果真实类别是第 3 类，那么损失较大。

损失函数把“预测错了”变成数值，反向传播才能计算梯度。没有 loss，优化器不知道参数该往哪个方向改。

## 适用场景

- 任何监督学习训练。
- 分类、回归、排序、生成、对比学习等任务。
- 需要比较不同模型和训练配置。
- 需要监控训练是否变好。

## 不适用场景

- 没有明确目标或标签的任务，不能直接套监督损失。
- 指标和损失不一致时，不能只看 loss。
- 高风险任务不能只靠平均 loss，要看分组表现和错误类型。
- 业务收益函数复杂时，简单分类 loss 可能不是最终目标。

## 前提、边界与反例

- 必要前提：目标定义清楚，预测输出和标签形状匹配，损失函数适合任务。
- 适用边界：loss 是训练代理目标，不一定等于业务目标。
- 反例或例外：推荐系统中 logloss 下降不一定代表线上收益提升。
- 结论可能失效的条件：标签噪声、类别极度不平衡、损失与指标错配。

## 对比与替代方案

| 任务 | 常见输出 | 常见损失 | 注意点 |
| --- | --- | --- | --- |
| 回归 | 连续数值 | MSE、MAE、Huber | 异常值会影响 MSE |
| 二分类 | 概率 | BCE | 注意类别不平衡 |
| 多分类 | 类别分布 | CE | logits 和标签形状要匹配 |
| 多标签 | 多个独立概率 | BCE | 每个标签独立判断 |
| 排序 | 相对顺序 | pairwise/listwise loss | 需贴近排序指标 |
| 生成 | token 分布 | CE/NLL | teacher forcing 和曝光偏差需理解 |

## 示例或最小实验

二分类点击预测：

```text
真实标签 y = 1
模型输出 logit = 2.0
sigmoid(logit) ≈ 0.88
```

预测点击概率 0.88，真实是点击，loss 较小。

如果：

```text
真实标签 y = 1
模型输出 logit = -2.0
sigmoid(logit) ≈ 0.12
```

模型很确信“不点击”，但真实点击，loss 很大。反向传播会把这个错误传回参数。

## 失败模式与风险

- 损失函数选错：回归任务用分类损失。
- 输出层处理错：对 logits 先 softmax 又传给内部自带 softmax 的损失。
- 二分类损失处理错：先 sigmoid 再传给 `BCEWithLogitsLoss`。
- 标签格式错：多分类标签 one-hot 和 class index 混用。
- 类别不平衡：模型预测多数类也能低 loss。
- 指标错配：loss 降了，业务指标没升。
- loss scale 异常：多任务 loss 权重不平衡。
- 数值不稳定：log、exp、softmax 使用不当导致 NaN。

## 常见误区

- 误区：loss 越低模型越好。
  - 修正：要看验证集、测试集、业务指标和错误类型。
- 误区：概率输出一定可信。
  - 修正：神经网络概率可能未校准。
- 误区：交叉熵只适合分类。
  - 修正：语言模型下一个 token 预测本质也是多分类交叉熵。
- 误区：训练 loss 不降就一定是模型太小。
  - 修正：可能是学习率、数据、标签、归一化、代码 bug。

## 实践判断

- 什么时候重点关注 loss：训练初期、调学习率、排查是否能学。
- 什么时候不能只看 loss：类别不平衡、排序、推荐、金融风控、高风险任务。
- 落地时最先验证什么：输出形状、标签形状、loss 是否符合任务、一个小 batch 能否过拟合。
- 可观察指标或检查点：train loss、validation loss、task metric、calibration、NaN rate。
