# 因子组合与特征交互

## 一句话结论

因子组合就是让模型学习“多个因素一起出现时会产生什么影响”；从线性组合到 FM、DeepFM 和 attention，本质都是在解决单个特征无法表达的交互关系。

## 概念定位

- 它是什么：建模特征之间相互作用的方法。
- 它不是什么：不是简单把字段拼接起来，也不是所有交互都越复杂越好。
- 相邻概念：feature crossing、factorization machine、wide and deep、DeepFM、attention、recommendation model。
- 前置知识：因子与特征、embedding、神经网络层、过拟合。

初学者可以先记住：

```text
单个因子：用户喜欢运动鞋。
组合因子：用户喜欢运动鞋 + 当前是雨天 + 商品是防水款，点击概率可能更高。
```

## 缩写全称速查

| 缩写 | 英文全称 | 中文解释 | 初学者理解 |
| --- | --- | --- | --- |
| FM | Factorization Machine | 因子分解机 | 用低维隐向量建模特征两两交互 |
| FFM | Field-aware Factorization Machine | 感知域的因子分解机 | 针对不同特征域使用不同交互向量 |
| DeepFM | Deep Factorization Machine | 深度因子分解机 | 把 FM 的低阶交互和深度网络的高阶交互结合 |
| CTR | Click-Through Rate | 点击率 | 推荐/广告里常见目标 |
| DNN | Deep Neural Network | 深度神经网络 | 多层神经网络，用于学习复杂非线性组合 |
| MLP | Multilayer Perceptron | 多层感知机 | 常用的全连接深度网络 |
| SVM | Support Vector Machine | 支持向量机 | 传统机器学习模型，FM 论文中常被对比 |
| ID | Identifier | 标识符 | 用户、商品、广告等离散编号 |

Feature crossing 不是缩写，意思是“特征交叉”，例如把 `城市=北京` 和 `品类=羽绒服` 组合成一个新特征。

## 核心概念

### 1. 线性组合

线性模型做的是：

```text
预测 = w1 * 特征1 + w2 * 特征2 + ... + b
```

它能表达每个特征单独的影响，但很难表达“两个特征同时出现才重要”的关系。

### 2. 手工特征交叉

例如：

```text
城市 = 北京
季节 = 冬天
交叉特征 = 北京_冬天
```

这能让模型学到“北京冬天”这个组合的特殊影响。但问题是：

- 需要人工经验。
- 组合数量爆炸。
- 稀疏组合很多，样本不足。

### 3. FM：学习两两交互

FM，全称 Factorization Machine，核心思想是：不用为每一对特征都单独学一个参数，而是为每个特征学一个低维向量，用向量内积表示两者交互强度。

直觉：

```text
用户 A 的向量 · 商品 B 的向量 = 用户 A 和商品 B 的匹配程度
```

这样即使某个具体组合很少出现，也能通过共享的隐向量学习到一部分交互规律。

### 4. DeepFM：低阶 + 高阶

DeepFM 试图同时捕捉：

- 低阶交互：例如两两特征组合。
- 高阶交互：多个因素通过深度网络形成复杂组合。

在推荐/广告场景，它的直觉是：

```text
FM 部分记住显著的二阶组合。
DNN 部分学习更复杂的非线性组合。
```

### 5. Attention

Attention 可以理解为“根据当前输入动态决定关注哪些因素”。在某些模型里，它能学习不同特征或 token 之间的依赖关系。

但注意：attention 不是“自动解释因果”。它只是模型内部的一种加权交互机制。

## 机制与原理

以广告点击率为例。

原始特征：

```text
用户 ID、广告 ID、城市、设备、时间、广告类目
```

可能的交互：

```text
用户 ID x 广告 ID
城市 x 广告类目
设备 x 时间
用户画像 x 广告类目 x 时间
```

不同方法处理方式：

| 方法 | 怎么组合 | 优点 | 风险 |
| --- | --- | --- | --- |
| 线性模型 | 不显式组合 | 简单、可解释 | 表达弱 |
| 手工交叉 | 人工创建组合特征 | 业务可控 | 组合爆炸 |
| FM | 自动建模两两交互 | 适合稀疏特征 | 主要是低阶交互 |
| DeepFM | FM + DNN | 兼顾低阶和高阶 | 更复杂，更难调 |
| Attention | 动态加权依赖 | 灵活 | 不一定稳定或可解释 |

## 适用场景

- 推荐系统、广告 CTR、搜索排序、风控、个性化匹配。
- 特征之间有明显组合效应。
- 高维稀疏离散特征很多。
- 单个特征弱，但组合特征强。
- 业务专家难以穷举所有有用交叉。

## 不适用场景

- 样本太少，复杂交互容易过拟合。
- 任务本身主要由单个特征决定。
- 需要强因果解释，不接受黑盒交互。
- 特征质量差，组合只会放大噪声。
- 线上延迟或内存不允许复杂模型。

## 前提、边界与反例

- 必要前提：特征定义稳定，样本量足够，验证集能反映真实分布。
- 适用边界：交互模型能学习统计关系，不保证发现因果关系。
- 反例或例外：如果特征交互来自业务硬规则，例如权限组合，应写规则，不应让模型学习。
- 结论可能失效的条件：交互特征极稀疏、冷启动严重、训练/线上分布不同。

## 对比与替代方案

| 方案 | 适合 | 优势 | 局限 |
| --- | --- | --- | --- |
| 手工交叉 | 少量关键组合 | 可解释、可控 | 依赖专家 |
| FM | 稀疏二阶交互 | 参数共享，适合推荐 | 高阶表达有限 |
| DeepFM | 低阶 + 高阶交互 | 端到端学习 | 调参复杂 |
| Wide & Deep | 记忆 + 泛化 | 工业推荐常见思路 | 需要设计 wide 特征 |
| Attention | 动态关系建模 | 灵活 | 成本高，不等于解释 |
| GBDT | 表格非线性组合 | 表格强基线 | 不一定适合大规模 ID embedding |

## 示例或最小实验

任务：预测用户是否点击广告。

单特征可能看不出：

```text
城市=上海 -> 点击率一般
广告类目=雨伞 -> 点击率一般
天气=下雨 -> 点击率一般
```

组合后：

```text
城市=上海 + 天气=下雨 + 广告类目=雨伞 -> 点击率明显升高
```

这就是特征交互的价值：组合影响不是单个因素简单相加。

## 失败模式与风险

- 组合爆炸：交叉特征太多，稀疏严重。
- 过拟合：模型记住训练集中特定 ID 组合。
- 冷启动：新用户、新商品没有足够交互历史。
- 数据泄露：组合中包含未来信息。
- 伪相关：模型学到偶然相关而非稳定规律。
- 可解释困难：复杂交互难以向业务说明。
- 线上不一致：训练中有某交互特征，线上无法实时生成。

## 常见误区

- 误区：因子组合越多越好。
  - 修正：组合越多越稀疏，越容易过拟合和增加成本。
- 误区：DeepFM 一定比 FM 好。
  - 修正：数据量、特征质量、调参和延迟都会影响效果。
- 误区：attention 权重就是因果解释。
  - 修正：attention 是模型内部权重，不等于因果贡献。
- 误区：神经网络会自动学到所有重要交互。
  - 修正：输入表示、样本覆盖和训练目标仍然限制学习。

## 实践判断

- 什么时候应该采用：推荐/广告/排序，且验证显示单特征模型不足。
- 什么时候应该谨慎：样本少、冷启动严重、解释要求强、线上计算预算有限。
- 落地时最先验证什么：简单线性/树模型基线，FM/DeepFM 是否带来稳定验证集提升。
- 可观察指标或检查点：AUC、logloss、calibration、线上 CTR/CVR、冷启动分组表现、特征交互覆盖率。
