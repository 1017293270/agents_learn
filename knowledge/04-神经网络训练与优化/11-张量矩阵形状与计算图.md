# 张量、矩阵形状与计算图

## 一句话结论

神经网络底层主要是在做张量运算；初学者真正跨过门槛，通常不是先背复杂公式，而是先看懂每一层输入、权重、输出和标签的 shape 是否对得上。

## 概念定位

- 它是什么：理解神经网络数据流、矩阵乘法、batch 维度、输出形状和计算图依赖关系的基础。
- 它不是什么：不是纯数学课，也不是必须先学完高等线性代数才能训练模型。
- 相邻概念：tensor、matrix multiplication、batch dimension、broadcasting、logits、computational graph。
- 前置知识：向量、矩阵、前向传播、损失函数。

初学者可以先记住：

```text
模型不是直接“思考文字”或“思考业务概念”。
模型看到的是一批张量。
每一层都把一个 shape 的张量变成另一个 shape 的张量。
```

## 缩写全称速查

| 缩写 | 英文全称 | 中文解释 | 初学者理解 |
| --- | --- | --- | --- |
| Tensor | Tensor | 张量 | 可以是一维、二维、三维或更高维的数值数组 |
| 2D | Two-Dimensional | 二维 | 表格或矩阵形状 |
| B | Batch Size | 批量大小 | 一次送入模型的样本数 |
| C | Number of Classes | 类别数 | 分类任务里可能的类别数量 |
| H | Hidden Size | 隐藏维度 | 神经网络中间表示的宽度 |
| MatMul | Matrix Multiplication | 矩阵乘法 | 神经网络线性层的核心计算 |
| DAG | Directed Acyclic Graph | 有向无环图 | 计算图常见结构 |

Shape 不是缩写，意思是张量形状，例如 `[32, 10]` 表示 32 条样本、每条 10 个特征。

## 核心概念

### 1. 标量、向量、矩阵、张量

| 名称 | 例子 | shape | 直觉 |
| --- | --- | --- | --- |
| 标量 | `3.14` | `[]` | 一个数 |
| 向量 | `[1.0, 2.0, 3.0]` | `[3]` | 一排数 |
| 矩阵 | `[[1,2],[3,4]]` | `[2,2]` | 二维表 |
| 张量 | 一批图片或一批样本 | `[B, C, H, W]` 等 | 更高维数组 |

神经网络里的“矩阵”通常只是张量的一种情况。真正通用的词是 tensor。

### 2. Batch 维度

模型通常不是一次只看一个样本，而是一次看一个 batch。

例如表格数据：

```text
X.shape = [32, 10]
```

含义：

- `32`：这批有 32 条样本。
- `10`：每条样本有 10 个特征。

### 3. 线性层的形状

PyTorch 的 `Linear(in_features, out_features)` 可以直觉理解为：

```text
Y = X @ W.T + b
```

如果：

```text
X.shape = [B, in_features]
W.shape = [out_features, in_features]
b.shape = [out_features]
```

那么：

```text
Y.shape = [B, out_features]
```

例子：

```text
X.shape = [32, 10]
Linear(10, 3)
输出 logits.shape = [32, 3]
```

这表示 32 条样本，每条样本输出 3 个类别分数。

### 4. Logits 和标签形状

多分类常见形状：

```text
logits.shape = [B, C]
target.shape = [B]
```

其中 `target` 里通常是类别索引，例如：

```text
target = [0, 2, 1, 1, ...]
```

二分类常见形状：

```text
logits.shape = [B, 1]
target.shape = [B, 1]
```

二分类如果使用 PyTorch `BCEWithLogitsLoss`，通常传入 raw logits，不需要先手动 sigmoid。

### 5. 计算图

计算图记录每一步张量运算的依赖关系。

```text
X -> Linear -> ReLU -> Linear -> logits -> loss
```

反向传播会沿着这个依赖链往回算梯度。如果你把中间结果 `.detach()`，或者转成普通 Python 数字，计算图可能断掉。

## 机制与原理

以一个最小 MLP 为例：

```text
输入 X:        [B, 10]
Linear(10,64): [B, 64]
ReLU:          [B, 64]
Linear(64,3):  [B, 3]
CrossEntropy: logits [B,3] + target [B] -> loss []
```

这里最关键的是：

- 每一层的输出 shape 必须能作为下一层输入。
- 损失函数要求预测和标签形状匹配。
- 最终 loss 通常是一个标量，才能对它做 `backward()`。

## 适用场景

- 看不懂 PyTorch 报错里的 shape mismatch。
- 不理解 `Linear(in_features, out_features)`。
- 写训练代码时不知道 logits 和 labels 应该是什么形状。
- 调试 batch、embedding、concat、flatten、view、reshape。
- 学大模型、推荐模型、金融因子模型之前补底层直觉。

## 不适用场景

- 只做概念讨论、不写代码时，可以先不追每个 shape。
- 已经被高层框架完全封装，短期只需要调用 API 时，可以先了解大概。
- 纯业务规则、数据库查询、权限判断，不需要神经网络张量计算。

但如果你要真正训练、调试或理解模型，shape 是绕不开的。

## 前提、边界与反例

必要前提：

- 输入特征已经数值化。
- 每个 batch 的字段形状一致。
- 标签形状符合损失函数要求。
- 模型每层的输入输出维度对得上。

反例：

```text
X.shape = [32, 10]
Linear(8, 3)
```

这里模型期待每条样本 8 个特征，但实际输入有 10 个特征，会报矩阵无法相乘的错误。

另一个反例：

```text
logits.shape = [32, 3]
target.shape = [32, 1]
```

如果用多分类交叉熵，target 通常应该是 `[32]` 的类别索引，而不是 `[32,1]` 的二维张量。

## 对比与替代方案

| 做法 | 好处 | 风险 |
| --- | --- | --- |
| 每层手写 shape 注释 | 最适合初学者理解 | 写起来慢 |
| 打印 batch 和 output shape | 快速定位问题 | 不能替代系统设计 |
| 使用高层 Trainer | 少写样板代码 | shape 错误时更难定位 |
| 用类型/shape 检查工具 | 更工程化 | 需要额外学习成本 |

## 示例或最小实验

二分类因子模型：

```text
输入：
X.shape = [64, 20]

模型：
Linear(20, 32)
ReLU
Linear(32, 1)

输出：
logits.shape = [64, 1]

标签：
y.shape = [64, 1]

损失：
BCEWithLogitsLoss(logits, y) -> scalar loss
```

多分类模型：

```text
输入：
X.shape = [64, 20]

模型：
Linear(20, 32)
ReLU
Linear(32, 5)

输出：
logits.shape = [64, 5]

标签：
y.shape = [64]

损失：
CrossEntropyLoss(logits, y) -> scalar loss
```

## 失败模式与风险

- 矩阵维度不匹配：`mat1 and mat2 shapes cannot be multiplied`。
- batch 维度被误删：`squeeze()` 把 `[1, C]` 变成 `[C]`。
- flatten 错维度：把 batch 维也压平了。
- target shape 错：多分类标签被做成 one-hot 或 `[B,1]`。
- 输出层错：二分类输出 `[B,2]` 却用二分类 loss，或输出 `[B,1]` 却用多分类 loss。
- broadcasting 意外生效：形状不一致但被自动扩展，结果看似能跑但含义错。
- dtype 错：分类标签应是整数索引，二分类概率标签通常是浮点。
- device 错：输入在 CPU，模型在 GPU。

## 常见误区

- 误区：只要代码能跑，shape 就是对的。
  - 修正：broadcasting 可能让错误 shape 也能运行，但训练含义错了。
- 误区：神经网络就是一堆矩阵乘法，所以不用管标签形状。
  - 修正：损失函数对 logits 和 target 有严格约定。
- 误区：输出概率才可以给 CrossEntropyLoss。
  - 修正：PyTorch `CrossEntropyLoss` 通常接收 raw logits。
- 误区：batch 维度不重要。
  - 修正：batch 维度贯穿训练、loss、指标和部署。

## 实践判断

写模型时建议固定一个 shape 表：

```text
X:      [batch_size, num_features]
hidden: [batch_size, hidden_size]
logits: [batch_size, num_classes]
y:      [batch_size]
loss:   scalar
```

调试顺序：

1. 打印第一个 batch 的输入和标签 shape。
2. 打印模型输出 shape。
3. 检查 loss 函数要求。
4. 检查 dtype 和 device。
5. 再开始调学习率或优化器。

## 来源与证据

- PyTorch `Linear` 文档支持输入最后一维为 `in_features`、输出最后一维为 `out_features` 的 shape 规则。
- PyTorch broadcasting 文档支持“可广播张量会自动扩展”的语义，因此它既是便利功能，也是潜在误用风险。
- PyTorch `CrossEntropyLoss` 文档支持分类任务中 input logits 与 target 的约定。
- 本节用入门方式重建 shape 检查流程，具体框架 API 仍需按当前版本验证。

### 关键主张表

| 主张 | 证据 | 来源 | 可信度 | 局限 |
| --- | --- | --- | --- | --- |
| 线性层保持除最后一维外的输入形状，并把最后一维映射到输出维 | PyTorch Linear 文档 | high | 其他层有不同 shape 规则 |
| CrossEntropyLoss 通常接收 logits 和类别 target | PyTorch CrossEntropyLoss 文档 | high | 也支持概率形式 target，初学阶段先掌握类别索引形式 |
| broadcasting 可能自动扩展形状 | PyTorch broadcasting 文档 | high | 是否错误取决于业务语义 |
| shape 错误是训练代码常见早期问题 | 工程实践 | medium | 具体错误依赖框架报错 |
