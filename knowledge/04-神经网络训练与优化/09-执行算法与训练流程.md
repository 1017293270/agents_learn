# 执行算法与训练流程

## 一句话结论

训练执行流程把数据读取、前向计算、反向传播、参数更新、日志记录、验证和保存串成可重复运行的循环；它决定了理论算法能否稳定、高效、可复现地跑起来。

## 概念定位

- 它是什么：神经网络训练在框架和硬件上的实际运行流程。
- 它不是什么：不是单个优化器公式，也不是只写 `model.fit()` 就结束。
- 相邻概念：DataLoader、batch、epoch、training loop、AMP、GPU、checkpoint、distributed training。
- 前置知识：前向传播、反向传播、优化器、学习率。

初学者可以先记住：

```text
训练不是只调用模型。
训练是一套循环：取数据 -> 算预测 -> 算 loss -> 反传 -> 更新 -> 记录 -> 验证 -> 保存。
```

## 缩写全称速查

| 缩写 | 英文全称 | 中文解释 | 初学者理解 |
| --- | --- | --- | --- |
| GPU | Graphics Processing Unit | 图形处理器 | 用于并行矩阵计算，加速训练 |
| CPU | Central Processing Unit | 中央处理器 | 通用计算处理器，负责数据加载、调度等 |
| TPU | Tensor Processing Unit | 张量处理器 | 专门面向机器学习计算的加速器 |
| RAM | Random Access Memory | 随机访问内存 | 主机内存 |
| VRAM | Video Random Access Memory | 显存 | GPU 上的内存 |
| AMP | Automatic Mixed Precision | 自动混合精度 | 自动使用不同数值精度来加速和省显存 |
| FP32 | 32-bit Floating Point | 32 位浮点数 | 单精度浮点，训练常见基准精度 |
| FP16 | 16-bit Floating Point | 16 位浮点数 | 半精度，省显存但数值范围小 |
| BF16 | Brain Floating Point 16 | bfloat16 浮点数 | 16 位浮点格式，动态范围比 FP16 更友好 |
| OOM | Out Of Memory | 内存不足 | 显存或内存不够导致训练失败 |
| I/O | Input/Output | 输入/输出 | 读数据、写日志、保存模型等操作 |

Epoch 不是缩写，指完整遍历训练集一次。Batch 是一小批样本。Step 通常指一次参数更新。

## 核心概念

### 1. Dataset 和 DataLoader

Dataset 负责定义“样本是什么、怎么取”。DataLoader 负责把样本组成 batch，并处理 shuffle、并行加载等。

### 2. Batch

Batch 是一次送入模型的一小批样本。

Batch size 影响：

- 显存占用。
- 梯度噪声。
- 训练速度。
- 泛化表现。

### 3. Epoch 和 step

```text
1 epoch = 训练集完整遍历一次
1 step = 通常指处理一个 batch 并更新一次参数
```

如果训练集有 10000 条，batch size 是 100，那么一个 epoch 大约有 100 steps。

### 4. Checkpoint

Checkpoint 是训练状态保存点，通常包括：

- model weights。
- optimizer state。
- scheduler state。
- epoch/step。
- random seed state。
- best metric。

只保存模型权重，可能无法完全恢复训练。

## 机制与原理

典型 PyTorch 风格训练循环：

```text
for epoch in range(num_epochs):
    model.train()
    for batch in train_loader:
        optimizer.zero_grad()
        outputs = model(batch.inputs)
        loss = loss_fn(outputs, batch.labels)
        loss.backward()
        optimizer.step()

    model.eval()
    with torch.no_grad():
        run_validation()

    save_checkpoint_if_needed()
```

### 训练模式和评估模式

`model.train()` 和 `model.eval()` 会影响 dropout、batch normalization 等层的行为。

常见错误：验证时忘记 `eval()`，导致指标不稳定。

### AMP 和混合精度

AMP 让部分操作用低精度运行，以节省显存、提高速度。

但需要注意：

- 可能需要 gradient scaling。
- 某些操作仍应保持 FP32。
- 数值异常要监控。

## 适用场景

- 自己写训练脚本。
- 微调模型。
- 训练推荐、图像、文本、表格模型。
- 排查训练慢、显存爆、指标不稳定。
- 需要可恢复训练和实验记录。

## 不适用场景

- 只做推理，不更新参数。
- 用高度封装平台且暂时不关心底层训练流程。
- 任务是规则系统或传统数据库流程。

但即使使用封装框架，理解训练循环仍然能帮助排查问题。

## 前提、边界与反例

- 必要前提：数据能稳定读取，模型和 batch 在同一设备，训练状态可记录。
- 适用边界：执行流程能提高稳定性，不修复错误模型目标。
- 反例或例外：只保存权重不保存 optimizer state，恢复训练后 loss 曲线可能突变。
- 结论可能失效的条件：多卡分布式、异步数据加载、混合精度、随机种子未固定。

## 对比与替代方案

| 执行方式 | 优势 | 局限 | 适合 |
| --- | --- | --- | --- |
| 手写 training loop | 可控、易调试 | 代码多 | 学习和研究 |
| 高层 Trainer | 快速、封装好 | 隐藏细节 | 常规训练 |
| AutoML 平台 | 自动搜索 | 不透明、成本高 | 快速业务验证 |
| 分布式训练 | 处理大模型大数据 | 复杂度高 | 大规模训练 |

## 示例或最小实验

最小训练流程检查清单：

```text
1. DataLoader 能取出一个 batch。
2. batch 输入形状正确。
3. model(batch) 输出形状正确。
4. loss 是有限数值。
5. loss.backward() 后参数有 grad。
6. optimizer.step() 后参数发生变化。
7. 一个小 batch 能被模型过拟合。
8. 验证时 model.eval() 生效。
9. checkpoint 能保存并恢复。
```

这比一开始追求大规模训练更可靠。

## 失败模式与风险

- OOM：batch 太大、模型太大、没有释放计算图。
- 数据加载慢：CPU/I/O 跟不上 GPU。
- 设备不一致：tensor 在 CPU，模型在 GPU。
- 忘记 eval：验证指标飘。
- 忘记 no_grad：验证占用显存。
- checkpoint 不完整：无法恢复优化器状态。
- 随机性不可控：实验无法复现。
- AMP 数值异常：梯度 underflow/overflow。
- 日志缺失：训练失败后无法复盘。

## 常见误区

- 误区：GPU 利用率低就是模型太小。
  - 修正：也可能是数据加载慢、batch 太小、I/O 阻塞。
- 误区：batch 越大越好。
  - 修正：大 batch 需要显存、学习率策略和泛化验证。
- 误区：保存模型权重就能恢复训练。
  - 修正：还要保存优化器、scheduler、step、随机状态。
- 误区：AMP 只会加速没有风险。
  - 修正：AMP 可能引入数值稳定性问题。

## 实践判断

- 什么时候重点优化执行流程：GPU 空闲、训练慢、OOM、恢复失败、指标不稳定。
- 什么时候先别上分布式：单卡流程还没稳定，数据和 loss 还没验证。
- 落地时最先验证什么：单 batch、单 epoch、小数据过拟合、checkpoint 恢复。
- 可观察指标或检查点：samples/sec、GPU utilization、VRAM usage、data loading time、step time、checkpoint size。
