# 失败模式与调参判断

## 一句话结论

神经网络调参不是随机改参数，而是根据训练曲线、验证曲线、梯度、数据和执行日志判断失败发生在哪一层：数据、模型、loss、梯度、优化器、正则、还是执行流程。

## 概念定位

- 它是什么：训练失败时的诊断框架和调参顺序。
- 它不是什么：不是一套固定神奇参数，也不是“loss 不降就换 Adam”。
- 相邻概念：overfitting、underfitting、gradient explosion、data leakage、learning rate tuning。
- 前置知识：前向传播、反向传播、优化器、学习率、执行流程。

初学者可以先记住：

```text
先确认数据和代码正确，再调模型和优化器。
否则调参只是把错误藏得更深。
```

## 缩写全称速查

| 缩写 | 英文全称 | 中文解释 | 初学者理解 |
| --- | --- | --- | --- |
| NaN | Not a Number | 非数值 | 数值计算崩掉的异常结果 |
| Inf | Infinity | 无穷大 | 溢出或除零等导致的无限值 |
| OOM | Out Of Memory | 内存不足 | 显存或内存不够 |
| LR | Learning Rate | 学习率 | 参数更新步长 |
| WD | Weight Decay | 权重衰减 | 控制参数大小的正则方式 |
| AUC | Area Under the Curve | 曲线下面积 | 分类/排序常用指标，尤其二分类排序能力 |
| MAE | Mean Absolute Error | 平均绝对误差 | 回归误差指标 |
| RMSE | Root Mean Squared Error | 均方根误差 | 回归误差指标 |
| P95 | 95th Percentile | 第 95 百分位 | 95% 请求低于该值，用于延迟等指标 |

Hyperparameter tuning 不是缩写，意思是超参数调优。

## 核心概念

### 1. 先区分训练问题和泛化问题

| 现象 | 可能问题 |
| --- | --- |
| 训练 loss 都不降 | 数据、loss、学习率、梯度、模型表达能力 |
| 训练好，验证差 | 过拟合、数据泄露、分布不一致 |
| 训练和验证都差 | 欠拟合、特征弱、模型小、训练不足 |
| loss NaN | 数值溢出、学习率过大、输入异常 |
| 指标不稳定 | batch 太小、验证集太小、随机性、数据加载问题 |

### 2. 过拟合

Overfitting 指模型在训练集表现好，但验证集或真实数据表现差。

常见处理：

- 更多数据。
- 数据增强。
- weight decay。
- dropout。
- early stopping。
- 降低模型容量。
- 检查数据泄露。

### 3. 欠拟合

Underfitting 指模型连训练集都学不好。

常见处理：

- 增大模型容量。
- 训练更久。
- 提高学习率或改善 scheduler。
- 改特征表示。
- 降低过强正则。
- 检查标签和 loss。

### 4. 梯度问题

梯度消失：

```text
早期层梯度很小，学不动。
```

梯度爆炸：

```text
梯度极大，参数更新过猛，loss 震荡或 NaN。
```

## 机制与原理

推荐排查顺序：

```text
1. 数据是否正确
2. 标签是否正确
3. 训练/验证划分是否正确
4. 模型输入输出形状是否正确
5. loss 是否正确
6. 一个小 batch 能否过拟合
7. 梯度是否存在且数值合理
8. 学习率是否合理
9. 正则是否过强或过弱
10. 再考虑换优化器或改模型结构
```

为什么要做“小 batch 过拟合”？

如果模型连 16 或 32 条样本都记不住，通常说明代码、loss、标签、学习率或模型结构有问题。它是训练管线健康检查。

## 适用场景

- loss 不降。
- 验证集指标差。
- 训练不稳定。
- 模型上线效果和离线不一致。
- 调优化器、学习率、batch size、正则前的系统排查。

## 不适用场景

- 数据和目标还没定义清楚时，调参意义很小。
- 指标本身不可靠时，调参会被错误信号带偏。
- 高风险业务只靠自动调参，不做人审和分组分析。

## 前提、边界与反例

- 必要前提：有训练/验证曲线，有基础日志，有可复现配置。
- 适用边界：诊断框架能缩小问题范围，不保证一次解决。
- 反例或例外：如果验证集泄露，所有调参结论都不可信。
- 结论可能失效的条件：分布漂移、样本太少、指标延迟反馈、随机性未控制。

## 对比与替代方案

| 调整手段 | 主要解决 | 可能副作用 |
| --- | --- | --- |
| 降低学习率 | 发散、震荡 | 学得慢 |
| 提高学习率 | 学得慢 | 发散 |
| 增大模型 | 欠拟合 | 过拟合、成本高 |
| 减小模型 | 过拟合、延迟 | 表达不足 |
| 加 weight decay | 过拟合 | 欠拟合 |
| 加 dropout | 过拟合 | 训练慢、欠拟合 |
| 增大 batch | 梯度更稳 | 显存高、泛化变化 |
| clip gradient | 梯度爆炸 | 阈值太小会学不动 |

## 示例或最小实验

### 情况 A：训练 loss 不降

优先检查：

```text
1. label 是否和 input 对齐。
2. loss 是否用对。
3. 模型输出 shape 是否正确。
4. 学习率是否太大或太小。
5. backward 后参数是否有 grad。
```

### 情况 B：训练 loss 降，验证 loss 升

优先检查：

```text
1. 是否过拟合。
2. 训练/验证分布是否一致。
3. 是否有数据泄露导致训练异常好。
4. 是否需要正则、早停或更多数据。
```

### 情况 C：loss 变 NaN

优先检查：

```text
1. 输入是否有 NaN/Inf。
2. loss 计算是否有 log(0)、除 0、exp 溢出。
3. 学习率是否过大。
4. 梯度范数是否爆炸。
5. AMP 是否需要 gradient scaling。
```

## 失败模式与风险

- 随机调参：没有假设，不记录实验。
- 指标污染：验证集被反复调参过拟合。
- 忽略数据：把标签错、泄露、分布漂移都归因于模型。
- 只看平均指标：少数群体或关键场景失败。
- 不保存配置：无法复现实验。
- 过度调参：为了离线指标牺牲线上稳定性。
- 没有基线：不知道复杂模型是否真的有收益。

## 常见误区

- 误区：loss 不降就是优化器不好。
  - 修正：更常见是数据、loss、学习率或代码问题。
- 误区：验证集好就一定能上线。
  - 修正：要看数据分布、时间切分、线上延迟、业务指标。
- 误区：过拟合只靠 dropout。
  - 修正：数据、正则、模型容量、早停、特征泄露都要看。
- 误区：调参越多越专业。
  - 修正：专业调参是有假设、有记录、有对照。

## 实践判断

- 什么时候先查数据：几乎总是先查，尤其 loss 异常和指标离谱时。
- 什么时候调学习率：loss 震荡、发散、下降过慢。
- 什么时候加正则：训练好、验证差，且排除泄露。
- 什么时候改模型：小 batch 能过拟合但验证仍差，或基线容量不足。
- 可观察指标或检查点：train/val curves、gradient norm、parameter norm、data drift、feature missing rate、seed variance。
