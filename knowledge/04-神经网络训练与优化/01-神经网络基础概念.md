# 神经网络基础概念

## 一句话结论

神经网络可以先理解为一个由许多可学习参数组成的函数，它把输入特征一步步变换成预测结果，训练就是不断调整这些参数，让预测更接近目标。

## 概念定位

- 它是什么：一类用多层参数化函数拟合输入到输出关系的机器学习模型。
- 它不是什么：不是“模拟大脑就自然有智能”，也不是不需要数据和损失函数的黑盒魔法。
- 相邻概念：linear model、multilayer perceptron、deep learning、feature representation、optimization。
- 前置知识：函数、向量、矩阵、特征、损失、梯度。

初学者可以先记住：

```text
输入特征 -> 神经网络层层计算 -> 输出预测
训练 = 用错误信号不断调整网络里的权重和偏置
```

| 缩写 | 英文全称 | 中文解释 | 初学者理解 |
| --- | --- | --- | --- |

| MLP | Multilayer Perceptron | 多层感知机 | 最基础的全连接前馈神经网络 |

| GPU | Graphics Processing Unit | 图形处理器 | 擅长并行矩阵计算，常用于神经网络训练 |

## 核心概念

### 1. 神经元

一个最简单的神经元可以理解为：

```text
输出 = 激活函数(输入1 * 权重1 + 输入2 * 权重2 + ... + 偏置)
```

其中：

- 权重决定某个输入有多重要。
- 偏置让模型即使输入为 0 也能有可调输出。
- 激活函数让模型具备非线性表达能力。

如果没有激活函数，多层线性变换叠在一起本质上仍然是线性模型，很难表达复杂关系。

### 2. 层

Layer 指神经网络中的一组计算。常见层：

| 层 | 作用 | 例子 |
| --- | --- | --- |
| Linear / Dense | 线性变换 | 表格特征分类 |
| Embedding | 离散 ID 到向量 | 用户 ID、词 ID |
| Convolution | 局部模式提取 | 图像边缘、纹理 |
| Normalization | 稳定分布 | BatchNorm、LayerNorm |
| Dropout | 随机丢弃部分激活 | 减少过拟合 |

### 3. 参数和超参数

| 类型 | 英文 | 是否训练得到 | 例子 |
| --- | --- | --- | --- |
| 参数 | Parameter | 是 | weight、bias、embedding table |
| 超参数 | Hyperparameter | 否，训练前或训练中人为设定 | learning rate、batch size、hidden size |

很多初学者会混淆：优化器更新的是参数，不是直接更新超参数。

### 4. 模型容量

Model capacity 指模型表达复杂函数的能力。容量太小，学不动复杂模式；容量太大，可能记住训练集噪声。

表现为：

- 欠拟合：训练集和验证集都差。
- 过拟合：训练集好，验证集差。

## 机制与原理

以一个 MLP 为例：

```text
x
  -> Linear
  -> ReLU
  -> Linear
  -> ReLU
  -> Linear
  -> logits
```

它每一层都在把输入变成新的表示：

- 第一层可能学到简单组合。
- 中间层可能学到更抽象的模式。
- 最后一层把模式转成任务输出。

训练时，模型先前向计算得到预测，再用损失函数衡量错误，再通过反向传播计算每个参数对错误的影响，最后用优化器更新参数。

## 适用场景

- 图像、文本、语音、推荐、表格、时间序列等复杂模式建模。
- 特征之间存在非线性关系。
- 数据量和计算资源足以支持模型训练。
- 人工规则难以穷举，或规则需要从数据中学习。

## 不适用场景

- 数据极少，简单规则或线性模型足够。
- 任务需要严格可解释且不能接受黑盒风险。
- 标签质量很差，模型会学习错误模式。
- 结构化查询任务，用数据库或规则更准确。
- 线上延迟、成本或安全约束不允许复杂模型。

## 前提、边界与反例

- 必要前提：有可学习的数据、明确目标、合适损失函数、可承受训练成本。
- 适用边界：神经网络擅长拟合复杂统计关系，不保证理解因果。
- 反例或例外：判断一个订单是否属于某用户，应优先用权限规则，不该让神经网络猜。
- 结论可能失效的条件：训练数据分布和真实使用分布差异大，标签噪声严重，特征泄露。

## 对比与替代方案

| 方法 | 优势 | 局限 | 适合 |
| --- | --- | --- | --- |
| 规则系统 | 可解释、可控 | 难覆盖复杂模式 | 合规、权限、确定流程 |
| 线性模型 | 简单、可解释、训练快 | 表达能力有限 | 基线、稀疏特征 |
| 树模型 | 表格数据强、调参相对友好 | 大规模端到端表示学习弱 | 结构化数据 |
| 神经网络 | 表达能力强、可端到端学习 | 需要数据、算力、调参 | 图像、文本、推荐、大规模模式 |

## 示例或最小实验

二分类任务：预测用户是否点击。

输入：

```text
用户年龄、设备类型、历史点击次数、广告类别
```

模型：

```text
特征向量 -> MLP -> 点击概率
```

训练目标：

```text
让点击样本的预测概率更接近 1，让未点击样本更接近 0。
```

这个例子里，网络不是“知道用户为什么点击”，而是从历史数据里学习输入特征和点击之间的统计关系。

## 失败模式与风险

- 数据泄露：训练时用了上线不可得的特征。
- 欠拟合：模型太小、特征弱、训练不足。
- 过拟合：模型太大、数据少、正则不足。
- 标签噪声：错误标签让模型学错。
- 分布漂移：上线数据和训练数据不同。
- 不可解释：难以知道某个预测具体因为什么。
- 误用概率：模型输出概率不一定校准。

## 常见误区

- 误区：层数越深越好。
  - 修正：更深意味着更高表达能力和训练难度，不保证更好。
- 误区：神经网络会自动找到所有有用特征。
  - 修正：输入表示、数据质量和归一化仍然关键。
- 误区：训练集效果好就是模型好。
  - 修正：要看验证集、测试集和真实业务表现。
- 误区：模型参数越多越聪明。
  - 修正：参数多只是容量大，是否有用取决于数据、目标和训练。

## 实践判断

- 什么时候应该采用：特征和目标关系复杂，规则难写，数据量充足。
- 什么时候应该谨慎：数据少、标签差、强解释要求、高风险决策。
- 落地时最先验证什么：简单基线、训练/验证曲线、数据泄露、标签质量。
- 可观察指标或检查点：training loss、validation loss、accuracy、AUC、calibration、inference latency。
