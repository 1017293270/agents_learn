## 一句话结论

机器学习建模不是“把数据丢给算法”，而是把一个现实问题改写成可学习、可验证、可复盘的预测任务。

## 概念定位

机器学习，英文是 Machine Learning，简称 ML。它的核心是：让模型从已有数据中学习输入和输出之间的统计关系，然后对新样本做预测或评分。

初学者最容易误解的一点是：模型不是在理解世界真相，它只是在给定数据、目标函数和训练方法下，学习一种能降低错误的映射关系。

一个完整建模流程通常包括：

1. 定义问题：要预测什么，预测给谁用，错了会怎样。
2. 定义标签：模型要学习的目标值是什么。
3. 收集数据：哪些样本、哪些字段、时间范围、数据来源。
4. 构造特征：把原始数据转成模型能使用的输入。
5. 划分数据：训练集、验证集、测试集。
6. 训练模型：选择算法和参数，让模型学习规律。
7. 评估模型：用指标和业务约束判断模型是否有用。
8. 解释和诊断：看模型依赖了什么，是否有泄露、偏差、过拟合。
9. 上线和监控：观察真实环境中的性能、延迟、漂移和失败。

## 核心概念

| 概念 | 英文 | 解释 |
| --- | --- | --- |
| 样本 | sample | 一条训练或预测记录，例如一只股票某天的数据 |
| 特征 | feature | 输入变量，例如估值、成交量、动量、波动率 |
| 标签 | label / target | 要预测的目标，例如未来收益、是否上涨、点击率 |
| 模型 | model | 从特征到预测值的函数 |
| 训练 | training / fitting | 用历史数据调整模型参数 |
| 推理 | inference / prediction | 用训练好的模型对新数据预测 |
| 损失函数 | loss function | 训练时衡量预测错误的函数 |
| 评价指标 | metric | 验证时衡量模型好坏的指标 |
| 泛化 | generalization | 模型在没见过的数据上仍然有效的能力 |
| 数据泄露 | data leakage | 训练时使用了预测时不该知道的信息 |

## 机制与原理

机器学习可以先用一个简单公式理解：

```text
预测值 = 模型(特征)
```

如果把特征记作 `X`，标签记作 `y`，模型参数记作 `θ`，训练的目标就是找到一组参数，让模型预测 `f(X; θ)` 和真实标签 `y` 尽量接近。

```text
训练目标 = 让 loss(f(X; θ), y) 尽可能小
```

这里有三个关键点：

1. 模型只能学习数据里存在的统计关系。
2. loss 下降不等于模型真的有用，因为它可能只是记住了训练数据。
3. 真正关心的是未来数据表现，所以必须用未参与训练的数据验证。

面向初学者，可以把建模理解成“做题训练”：

- 训练集像练习题，模型在这里学习。
- 验证集像模拟考试，用来调模型和选模型。
- 测试集像最终考试，尽量只在最后使用一次。
- 线上数据像真实工作，分布可能和考试题不同。

## 适用场景

适合使用机器学习的场景通常具有这些特征：

- 有足够历史数据。
- 存在可学习的统计规律。
- 目标可以定义成相对明确的标签或评分。
- 人工规则难以覆盖全部情况。
- 预测错误的成本可被评估和控制。

例子：

- 根据用户行为预测是否点击。
- 根据交易数据识别异常。
- 根据文本特征分类工单类型。
- 根据历史行情和财务数据预测某种风险或收益排序。

## 不适用场景

以下场景不适合直接上机器学习：

- 没有可靠标签。
- 数据量太少且噪声很高。
- 目标定义不断变化。
- 错误代价极高但无法解释或控制。
- 业务规则非常清晰，用规则系统就能解决。
- 历史数据不能代表未来，例如制度突然变化、市场结构突变。

金融场景尤其要小心：历史上有效的规律，未来可能消失；回测表现很好，也可能只是过拟合、数据泄露或选择偏差。

## 前提、边界与反例

机器学习的前提不是“算法够强”，而是以下条件基本成立：

- 训练数据和未来数据有一定相似性。
- 标签能代表真正要优化的问题。
- 特征在预测时可以真实获得。
- 验证方式模拟了未来使用方式。
- 指标和业务目标没有严重错位。

反例：

- 用明天收盘价构造今天的特征，模型表现会异常好，但真实预测时无法使用。
- 用随机划分验证时间序列金融数据，训练集中可能包含验证集之后的信息，导致评估偏乐观。
- 只优化准确率 Accuracy，在类别极度不平衡时可能得到一个毫无业务价值的模型。

## 对比与替代方案

| 方法 | 适合情况 | 局限 |
| --- | --- | --- |
| 人工规则 | 逻辑清楚、规则稳定、可解释性要求高 | 难以覆盖复杂非线性关系 |
| 统计分析 | 需要解释关系、检验假设 | 预测能力可能有限 |
| 传统机器学习 | 表格数据、结构化预测、样本中等 | 需要特征工程和验证设计 |
| 深度学习 | 图像、语音、文本、大规模复杂模式 | 数据、算力、调参和解释成本高 |
| 大模型 API | 自然语言理解、生成、工具调用 | 不适合直接替代严谨数值预测流程 |

## 示例或最小实验

假设你要预测“某只股票未来 5 个交易日收益是否为正”。

错误做法：

```text
把所有历史数据随机打散，训练一个模型，看准确率。
```

问题：

- 时间顺序被破坏。
- 训练数据可能包含未来市场状态。
- 准确率未必对应赚钱能力。

更合理的最小流程：

```text
1. 定义标签：未来 5 日收益 > 0 记为 1，否则记为 0。
2. 定义特征：只使用预测日以前能得到的信息，例如过去收益、成交量、估值。
3. 按时间划分：早期训练，中期验证，后期测试。
4. 训练基线：先用逻辑回归或简单树模型。
5. 评价指标：看 AUC、分组收益、换手、最大回撤等。
6. 检查泄露：确认所有特征在预测时点可用。
7. 解释模型：看哪些特征贡献最大，是否符合基本常识。
```

## 失败模式与风险

| 失败模式 | 表现 | 后果 |
| --- | --- | --- |
| 标签定义错误 | 模型学到的目标和真实业务不一致 | 指标好但实际无用 |
| 数据泄露 | 验证分数异常高 | 上线后崩溃 |
| 过拟合 | 训练好、验证差 | 泛化失败 |
| 指标错配 | 优化了错误指标 | 决策价值低 |
| 分布漂移 | 历史规律未来失效 | 长期性能下降 |
| 样本选择偏差 | 只看幸存样本或特定时期 | 结论不可推广 |

## 常见误区

- 误区一：模型越复杂越好。  
  复杂模型更容易拟合噪声，尤其在样本少、噪声大、验证不严谨时。

- 误区二：训练集分数高就说明模型好。  
  真正重要的是未见数据表现。

- 误区三：指标高就一定能上线。  
  还要看成本、延迟、稳定性、解释性、错误代价和业务约束。

- 误区四：有大模型 API 就不需要机器学习基础。  
  大模型可以帮你写代码、解释概念、生成实验，但不能替你完成严谨的数据定义、验证设计和因果判断。

## 实践判断

初学者做建模时，建议永远先问五个问题：

1. 我到底在预测什么？
2. 这个标签是否真实代表目标？
3. 这些特征在预测时是否真的可用？
4. 验证方式是否模拟未来使用场景？
5. 如果模型错了，我能否发现并控制损失？

如果这五个问题回答不清楚，不要急着调模型参数。

## 待验证问题

- 如果后续使用真实金融因子，标签应定义为绝对收益、超额收益、风险调整收益，还是分位排序？
- 当前任务更适合分类、回归还是排序？
- 数据频率是日频、分钟级还是事件级？不同频率会改变验证方式。
- 是否需要将交易成本、滑点和可交易性纳入评价指标？
