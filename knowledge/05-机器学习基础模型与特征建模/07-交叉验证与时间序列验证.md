## 一句话结论

交叉验证用于估计模型在未见数据上的表现；但时间序列和金融数据不能随便随机打散，必须尊重时间顺序和信息可得性。

## 概念定位

交叉验证，英文是 Cross-validation，简称 CV。它把数据分成多个训练和验证组合，用多次验证结果估计模型泛化能力。

时间序列验证，英文可写作 Time Series Validation，常见做法是按时间向前滚动训练和验证。

对普通独立同分布数据，K-fold cross-validation 很常见；对时间序列和金融数据，随机 K-fold 往往不合适，因为它可能让未来信息进入训练过程。

## 核心概念

| 概念 | 解释 |
| --- | --- |
| Train set | 训练集，用于模型学习 |
| Validation set | 验证集，用于调参和选择模型 |
| Test set | 测试集，用于最终评估 |
| K-fold | 把数据分成 K 份，轮流验证 |
| Stratified K-fold | 分类任务中保持类别比例的 K-fold |
| TimeSeriesSplit | 按时间顺序切分的验证方式 |
| Walk-forward | 训练窗口逐步向前滚动 |
| Purging | 去掉训练集中与验证标签时间重叠的样本 |
| Embargo | 在验证集附近留出隔离区，降低泄露 |

## 机制与原理

普通 K-fold：

```text
数据分成 5 份：
第 1 次：1 份验证，4 份训练
第 2 次：换另一份验证
...
最后平均 5 次结果
```

时间序列验证：

```text
训练：1月-6月，验证：7月
训练：1月-7月，验证：8月
训练：1月-8月，验证：9月
```

或者滚动窗口：

```text
训练：1月-6月，验证：7月
训练：2月-7月，验证：8月
训练：3月-8月，验证：9月
```

核心原则：

```text
训练数据的时间必须早于验证数据。
```

## 适用场景

K-fold 适合：

- 样本近似独立同分布。
- 时间顺序不重要。
- 数据没有明显主体或时间泄露。

Stratified K-fold 适合：

- 分类任务。
- 类别比例不均衡。

Time series split 适合：

- 时间序列预测。
- 金融因子。
- 用户行为随时间变化。
- 线上场景需要模拟未来预测。

## 不适用场景

不应随机交叉验证的情况：

- 股票、价格、交易、宏观数据等时间序列。
- 标签使用未来窗口，例如未来 5 日收益。
- 同一用户或同一资产的样本高度相关。
- 训练和验证之间可能存在事件重叠。
- 数据存在明显生产时间和可得时间。

## 前提、边界与反例

反例：

```text
用 2020-2025 年股票数据随机打散做 K-fold。
训练集中包含 2025 年数据，验证集中包含 2021 年数据。
```

这等于让模型在训练时看到未来市场环境，然后回头预测过去，评估会偏乐观。

另一个反例：

```text
标签是未来 20 日收益。
训练样本日期和验证样本日期相隔太近，标签窗口重叠。
```

这时训练标签和验证标签可能共享同一段未来收益，需要考虑 purging 或 embargo。

## 对比与替代方案

| 方法 | 适合 | 不适合 |
| --- | --- | --- |
| Holdout | 简单快速基线 | 样本少时不稳定 |
| K-fold | 独立同分布数据 | 时间序列 |
| Stratified K-fold | 分类且类别不平衡 | 时间序列 |
| Group K-fold | 同一主体不能跨训练验证 | 没有分组结构的数据 |
| TimeSeriesSplit | 时间序列预测 | 强季节性或结构突变时仍需补充分析 |
| Walk-forward | 模拟逐步上线 | 计算成本更高 |

## 示例或最小实验

目标：用 2020-2024 年数据预测未来 5 日收益。

更合理的划分：

```text
训练：2020-2021，验证：2022
训练：2020-2022，验证：2023
训练：2020-2023，测试：2024
```

如果用滚动窗口：

```text
训练：2020-2021，验证：2022Q1
训练：2020Q2-2022Q1，验证：2022Q2
训练：2020Q3-2022Q2，验证：2022Q3
```

检查项：

```text
1. 每个验证窗口都在训练窗口之后。
2. 特征只使用预测时点之前的信息。
3. 预处理器只在训练窗口 fit。
4. 如果标签窗口重叠，考虑留出隔离区。
```

## 失败模式与风险

| 风险 | 解释 |
| --- | --- |
| 随机切分时间数据 | 未来信息进入训练 |
| 预处理全量 fit | 验证集统计信息泄露 |
| 多次试错测试集 | 测试集变成验证集 |
| 标签窗口重叠 | 训练和验证共享未来收益 |
| 分组泄露 | 同一主体同时出现在训练和验证 |
| 只报最好窗口 | 选择性报告导致乐观偏差 |

## 常见误区

- 误区一：交叉验证越复杂越可靠。  
  验证方式必须匹配数据生成过程，而不是越复杂越好。

- 误区二：金融数据也可以随机打散。  
  多数金融预测要模拟“用过去预测未来”。

- 误区三：测试集可以反复调参。  
  反复看测试集会把测试集污染成验证集。

## 实践判断

对于金融因子，优先使用时间切分，并记录：

- 训练窗口长度。
- 验证窗口长度。
- 测试窗口。
- 标签预测周期。
- 是否存在标签重叠。
- 是否使用 purging 或 embargo。
- 每个窗口单独表现，而不是只看平均。

## 来源与证据

- scikit-learn cross-validation 文档支持交叉验证、K-fold、stratified K-fold、TimeSeriesSplit 等基础方法。
- purging 和 embargo 在本节中作为金融时间序列风险控制概念提出，后续应补充专门金融机器学习资料。

## 待验证问题

- 后续因子数据标签窗口是多少天？是否需要 purging？
- 样本是否按股票分组，是否需要 group split？
- 训练窗口应使用 expanding window 还是 rolling window？
- 是否存在市场 regime change，需要按阶段单独评估？
