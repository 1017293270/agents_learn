## 一句话结论

过拟合是模型把训练数据里的噪声也学进去了；正则化、验证集、早停和谨慎的模型选择，都是为了让模型在未来数据上更可靠。

## 概念定位

过拟合，英文是 Overfitting，指模型在训练数据上表现很好，但在新数据上表现明显变差。

欠拟合，英文是 Underfitting，指模型太简单，连训练数据中的主要规律都没学到。

正则化，英文是 Regularization，指在训练目标中加入约束，让模型不要过度复杂。

模型选择，英文是 Model Selection，指在多个模型、特征、参数和验证结果中选择最终方案。

## 核心概念

| 概念 | 解释 |
| --- | --- |
| Bias | 偏差，模型过于简单带来的系统性错误 |
| Variance | 方差，模型对训练数据扰动过于敏感 |
| Bias-variance tradeoff | 偏差-方差权衡 |
| Hyperparameter | 超参数，训练前设定的参数 |
| Regularization | 正则化，控制复杂度 |
| Early stopping | 早停，验证集不提升时停止训练 |
| Validation curve | 观察参数变化对训练和验证表现的影响 |
| Nested CV | 嵌套交叉验证，用于更严谨估计模型选择后的表现 |

## 机制与原理

可以用“背题”和“会做题”理解过拟合。

如果学生把练习题答案背下来了，练习题满分，但新题不会，这就是过拟合。

模型也是一样：

```text
训练集表现很好
验证集表现很差
```

通常说明模型学到了训练集里的偶然噪声。

正则化的直觉：

```text
不要让模型参数太大、树太深、规则太复杂、训练轮数太多。
```

模型选择的关键是：你不能只挑历史结果最好的一次，因为多次尝试本身也会制造过拟合。

## 适用场景

需要重点控制过拟合的场景：

- 样本量少。
- 特征很多。
- 标签噪声高。
- 模型复杂。
- 调参次数很多。
- 目标分布随时间变化。
- 金融市场、广告点击、推荐排序等高噪声任务。

## 不适用场景

不要滥用正则化：

- 模型明显欠拟合时，继续加正则化会更差。
- 数据严重错误时，正则化解决不了标签定义问题。
- 验证方式错误时，正则化会给你一种虚假的安全感。
- 强业务约束问题中，单纯追求验证分数不够。

## 前提、边界与反例

一个常见反例：

```text
你尝试了 200 组参数，然后只报告测试集最高的一组。
```

这不是可靠模型选择。因为测试集已经参与了选择过程，它不再是纯粹的样本外评估。

更稳妥：

```text
训练集：训练模型。
验证集：选择参数。
测试集：只做最终一次评估。
```

如果需要更严谨，可以使用嵌套交叉验证：内层选参数，外层估计泛化表现。

## 对比与替代方案

| 方法 | 作用 | 边界 |
| --- | --- | --- |
| L1 正则化 | 产生稀疏特征选择效果 | 对相关特征可能不稳定 |
| L2 正则化 | 平滑参数，降低方差 | 不会自动删除特征 |
| Dropout | 神经网络中随机丢弃部分激活 | 不适用于所有模型 |
| Early stopping | 防止训练轮数过多 | 验证集必须可靠 |
| 限制树深 | 控制树模型复杂度 | 太浅会欠拟合 |
| 交叉验证 | 更稳估计泛化能力 | 时间序列需特殊切分 |

## 示例或最小实验

你训练一个 GBDT 模型：

```text
训练集 AUC = 0.95
验证集 AUC = 0.54
```

这通常是过拟合或泄露检查失败。

排查顺序：

```text
1. 检查训练/验证时间切分。
2. 检查特征是否含未来信息。
3. 降低 max_depth。
4. 增加 min_samples_leaf 或类似约束。
5. 降低 learning_rate，配合 early stopping。
6. 减少特征数量或删除可疑特征。
7. 用更简单模型做基线对照。
```

## 失败模式与风险

| 风险 | 解释 |
| --- | --- |
| 调参过拟合 | 调太多次导致验证集被“学会” |
| 测试集污染 | 反复用测试集选模型 |
| 复杂模型崇拜 | 忽略简单模型已足够 |
| 只看平均指标 | 掩盖某些时间窗口崩溃 |
| 正则化误用 | 欠拟合时还继续加约束 |
| 选择性报告 | 只报告最好结果 |

## 常见误区

- 误区一：验证集表现好就一定能上线。  
  验证集只是估计，真实线上仍可能分布漂移。

- 误区二：调参越多越专业。  
  没有严格验证的调参只是扩大碰运气空间。

- 误区三：正则化一定提高分数。  
  正则化提高的是泛化稳定性的可能性，不保证分数必然上升。

## 实践判断

初学者应记录每次模型选择：

- 使用哪些特征。
- 使用哪些参数。
- 验证窗口如何划分。
- 主指标和辅助指标。
- 是否有泄露检查。
- 为什么选择这个模型，而不是只因为它分数最高。

金融场景尤其建议：

- 不只看总体平均。
- 分年份、分市场状态、分行业检查。
- 关注模型稳定性，而不是单次最高分。
