## 一句话结论

模型解释能帮助你看模型依赖了哪些特征，但解释结果不是因果证明，也不能替代严格验证。

## 概念定位

模型解释，英文是 Model Interpretability，指理解模型为什么做出某个预测，或整体上依赖哪些特征。

特征重要性，英文是 Feature Importance，指衡量某个特征对模型预测或指标的贡献程度。

常见解释方法：

- 线性模型系数。
- 树模型自带重要性。
- Permutation importance，置换重要性。
- Partial Dependence Plot，部分依赖图。
- ICE，Individual Conditional Expectation，个体条件期望图。
- SHAP，SHapley Additive exPlanations，基于 Shapley value 的加性解释方法。

## 核心概念

| 概念 | 解释 |
| --- | --- |
| Global explanation | 全局解释，理解模型整体行为 |
| Local explanation | 局部解释，理解单个样本预测 |
| Coefficient | 线性模型系数 |
| Impurity importance | 树模型基于分裂纯度的默认重要性 |
| Permutation importance | 打乱某个特征，看模型性能下降多少 |
| PDP | Partial Dependence Plot，显示某特征变化时预测平均变化 |
| ICE | 显示每个样本在特征变化时预测如何变化 |
| SHAP | 用博弈论思想分配特征贡献 |

## 机制与原理

不同解释方法回答的问题不同。

线性模型系数回答：

```text
在其他特征固定且模型假设成立时，这个特征增加会让预测往哪个方向变化？
```

树模型重要性回答：

```text
这个特征在树分裂中减少了多少不纯度？
```

Permutation importance 回答：

```text
如果我打乱这个特征，模型指标会下降多少？
```

SHAP 回答：

```text
对这个样本的这次预测，各特征分别贡献了多少？
```

注意：这些问题都不是“这个特征是否导致了结果”。

## 适用场景

模型解释适合：

- 检查模型是否依赖可疑特征。
- 判断特征方向是否符合常识。
- 发现数据泄露。
- 进行模型审查和沟通。
- 比较模型在不同时间窗口的稳定性。
- 金融因子中检查因子贡献是否过度集中。

## 不适用场景

解释方法不适合直接用于：

- 证明因果关系。
- 替代样本外验证。
- 证明策略能赚钱。
- 在高度相关特征中精确分配真实贡献。
- 解释超出训练分布的预测。

## 前提、边界与反例

反例：

```text
模型显示“成交量”特征很重要。
```

这不意味着成交量导致未来收益。可能原因包括：

- 成交量和其他因子相关。
- 成交量捕捉了市场状态。
- 数据中存在行业或市值偏差。
- 特征构造方式存在泄露。
- 模型只是利用了历史样本中的偶然关系。

另一个反例：

两个特征高度相关：

```text
market_cap 和 log_market_cap
```

模型可能把重要性分给其中一个，也可能在不同训练中互换。此时单个特征重要性不稳定。

## 对比与替代方案

| 方法 | 优点 | 风险 |
| --- | --- | --- |
| 线性系数 | 简单直观 | 受标准化、共线性和线性假设影响 |
| 树默认重要性 | 计算方便 | 可能偏向高基数或连续特征 |
| Permutation importance | 更贴近模型性能 | 相关特征下解释会变复杂 |
| PDP | 展示平均影响 | 特征相关时可能生成不现实样本 |
| ICE | 能看个体差异 | 图多时难解释 |
| SHAP | 局部解释强，表达细 | 计算成本和误读风险较高 |

## 示例或最小实验

假设模型特征重要性排名：

```text
1. future_return_lag_0
2. momentum_20d
3. volatility_20d
```

第一名叫 `future_return_lag_0`，非常可疑。

排查：

```text
1. 这个字段是否包含当天或未来收益？
2. 预测时点是否能获得？
3. 是不是标签计算过程中的中间字段？
4. 删除它后，验证分数是否大幅下降？
```

如果删除后模型崩溃，说明之前的好表现可能来自泄露。

## 失败模式与风险

| 风险 | 解释 |
| --- | --- |
| 把相关当因果 | 解释的是模型依赖，不是现实因果 |
| 忽视共线性 | 高相关特征导致重要性分配不稳定 |
| 只解释训练集 | 训练集解释可能掩盖过拟合 |
| 忽视时间稳定 | 特征重要性可能随市场阶段变化 |
| 图表误读 | PDP/SHAP 图看起来精确，但仍依赖假设 |
| 解释遮羞 | 用解释图掩盖验证不足 |

## 常见误区

- 误区一：特征重要性越高，因子越好。  
  因子好不好要看稳定性、样本外表现和经济含义。

- 误区二：SHAP 能解释一切。  
  SHAP 是解释工具，不是因果工具，也不自动解决数据问题。

- 误区三：解释结果稳定就说明模型可靠。  
  还要看验证方式和未来表现。

## 实践判断

金融因子模型解释时，至少检查：

- 重要特征是否可在预测时点获得。
- 重要性是否跨时间窗口稳定。
- 是否集中在少数可疑字段。
- 是否和行业、市值、流动性暴露混淆。
- 删除最重要特征后模型是否完全崩溃。
- 解释方向是否符合基本经济直觉。

## 待验证问题

- 后续模型解释是否需要专门引入 SHAP？
- 因子重要性是否应按年份、行业、市值分层检查？
- 是否需要建立“可疑特征清单”和泄露排查流程？
- 如何把解释结果和实际交易约束连接起来？
