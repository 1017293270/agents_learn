## 一句话结论

特征工程是把原始数据变成模型可学习信号的过程，预处理必须放进训练验证流程内部，否则很容易把未来信息泄露给模型。

## 概念定位

特征工程，英文是 Feature Engineering，指构造、清洗、变换和选择模型输入特征。

数据预处理，英文是 Preprocessing，指模型训练前对数据做缺失处理、缩放、编码、去极值等操作。

很多初学者以为模型效果主要取决于算法，其实在表格数据和金融因子中，特征定义、时间对齐、缺失处理和泄露控制往往更重要。

## 核心概念

| 概念 | 解释 |
| --- | --- |
| 缺失值 | 数据为空或不可用 |
| 异常值 | 极端偏离常规范围的数据 |
| 标准化 | 减去均值、除以标准差 |
| 归一化 | 把数值缩放到特定范围 |
| 类别编码 | 把类别变量转成模型可用数值 |
| One-hot | 独热编码，每个类别一个 0/1 特征 |
| Target encoding | 用目标统计编码类别，必须严控泄露 |
| Pipeline | 把预处理和模型训练串成统一流程 |
| 数据泄露 | 训练时使用了预测时不该知道的信息 |

## 机制与原理

模型只能接收数值或结构化输入，因此原始数据通常要处理。

例如：

```text
原始数据：
股票代码、交易日期、市值、成交量、行业、过去收益、财务指标

处理后：
标准化市值、成交量变化率、行业 one-hot、过去 20 日动量、过去 20 日波动率
```

特征工程的关键不是“做很多特征”，而是：

1. 特征是否和目标有可能相关。
2. 特征是否在预测时点可用。
3. 特征是否稳定。
4. 特征是否引入泄露。
5. 特征是否让模型更容易学习。

## 适用场景

几乎所有机器学习项目都需要预处理：

- 线性模型通常需要标准化。
- 树模型通常不需要标准化，但需要缺失、异常和类别处理。
- 神经网络通常对缩放、分布和数值稳定性更敏感。
- 金融因子通常需要去极值、标准化、中性化和时间对齐。

## 不适用场景

不要为了“看起来专业”盲目做特征工程：

- 不理解含义的特征不要乱加。
- 不能在预测时获得的特征不能用。
- 用全量数据计算的均值、标准差、分位数可能泄露未来。
- 过度构造特征会增加过拟合风险。
- 金融因子不能只看统计相关，还要看可交易性和稳定性。

## 前提、边界与反例

最典型的泄露反例：

```text
你用全部数据计算标准化均值和标准差，再切训练集和测试集。
```

这看似只是预处理，但测试集信息已经参与了训练变换。

更严谨做法：

```text
1. 在训练集上 fit 预处理器。
2. 用训练集学到的均值、标准差、编码规则 transform 验证集和测试集。
3. 交叉验证时，每一折都只在当前训练折 fit 预处理器。
```

金融中的时间泄露还可能来自：

- 财报发布日期和报告期混淆。
- 使用未来复权价格计算历史特征。
- 用未来成分股列表筛选历史样本。
- 用全样本分位数做因子分组。

## 对比与替代方案

| 处理方式 | 适合 | 风险 |
| --- | --- | --- |
| 标准化 | 线性模型、神经网络、距离模型 | 必须只在训练数据 fit |
| 归一化 | 需要固定范围的输入 | 极端值会影响缩放 |
| 去极值 | 金融因子、异常值明显数据 | 可能误删真实尾部信息 |
| One-hot 编码 | 低基数类别 | 高基数时维度膨胀 |
| Target encoding | 高基数类别 | 极易泄露，必须交叉拟合 |
| 缺失指示器 | 缺失本身有信息 | 可能学习到采集流程偏差 |

## 示例或最小实验

目标：预测未来 5 日收益。

特征：

- `return_20d`
- `volatility_20d`
- `turnover_20d`
- `market_cap`
- `industry`

合理流程：

```text
1. 按日期排序。
2. 只使用预测日以前的数据构造 rolling 特征。
3. 在训练窗口内计算去极值阈值和标准化参数。
4. 对验证/测试窗口只 transform，不重新 fit。
5. 对行业做 one-hot 或中性化处理。
6. 保存每一步处理规则，方便复现。
```

## 失败模式与风险

| 风险 | 表现 |
| --- | --- |
| 全量标准化泄露 | 测试集表现虚高 |
| 标签穿越 | 特征直接或间接包含未来标签 |
| 异常值污染 | 模型被极端样本牵引 |
| 类别编码泄露 | target encoding 使用了验证标签 |
| 特征膨胀 | 特征太多导致过拟合 |
| 时间对齐错误 | 实际预测时拿不到该特征 |

## 常见误区

- 误区一：树模型不需要任何预处理。  
  不需要标准化不等于不需要缺失、异常、编码和泄露检查。

- 误区二：特征越多越好。  
  特征越多，越需要更严格的验证和正则化。

- 误区三：标准化是无害操作。  
  用未来数据计算标准化参数就是泄露。

- 误区四：金融因子只要相关就能用。  
  还要看时效性、稳定性、交易成本、拥挤度和可解释性。

## 实践判断

做特征工程前先写下：

```text
这个特征在真实预测那一刻是否已经可见？
这个变换的参数是否只由训练数据学到？
这个特征的经济含义或业务含义是什么？
```

如果回答不清楚，先不要把它放进模型。

## 来源与证据

- scikit-learn preprocessing 文档支持标准化、归一化、编码等预处理概念。
- scikit-learn cross-validation 文档支持将训练和验证流程隔离，以避免评估偏差。
- 金融因子部分属于实践风险总结，需结合真实数据源和时间戳进一步验证。

## 待验证问题

- 真实因子数据中，缺失值代表“无数据”还是“该指标不适用”？
- 因子标准化应按全市场、行业内还是风格分组进行？
- 是否需要做 winsorization、rank transform 或 z-score？
- 财务数据发布日期是否严格可得？
